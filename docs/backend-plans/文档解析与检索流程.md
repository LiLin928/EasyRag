## 概述

EasyRAG 系统采用多阶段处理流程：

```
文档上传 → 解析 → 元素提取 → 树结构构建 → 分块 → 向量化 → 存储
                                    ↓                    ↓
                              文档导航             向量检索
```

### 核心概念

| 概念 | 说明 | 用途 |
|------|------|------|
| **Element（元素）** | 文档的最小语义单元（段落、标题、表格等） | 数据存储的基本单位 |
| **Tree Node（树节点）** | 基于标题层级构建的章节节点 | 文档导航、结构展示 |
| **Chunk（分块）** | 基于文本长度组织的检索单元 | 向量检索 |

## 文档解析流程

### 完整流程图

```
用户上传文档
    ↓
Celery 任务调度
    ↓
1. 获取文件 (从 MinIO/本地存储)
    ↓
2. 文档解析 (Dispatcher → Parser)
    ↓   ├─ PDF: PyMuPDF 提取文本块
    ↓   ├─ DOCX: python-docx 提取段落和表格
    ↓   ├─ XLSX: openpyxl 提取工作表
    ↓   └─ MD: 正则解析标题和段落
    ↓
    输出: List[DocumentElement]
    ↓
3. 构建文档树 (TreeBuilder)
    ↓   - 识别标题层级
    ↓   - 构建树结构
    ↓   - 分配元素到节点
    ↓
    输出: DocumentTree + 元素关联
    ↓
4. 保存到数据库
    ↓   - doc_tree_nodes: 树节点
    ↓   - element_positions: 元素
    ↓
5. 分块处理 (Chunker)
    ↓   - 按长度分块（512字符）
    ↓   - 保留重叠（50字符）
    ↓
    输出: List[Chunk]
    ↓
6. 保存 Chunk 到数据库
    ↓
7. 向量化 (Embedder)
    ↓   - 调用 Embedding API
    ↓   - 存储向量到数据库
    ↓
完成
```

### 代码入口

```python
# backend/app/worker/tasks/parse_tasks.py

async def _parse_document_async(
    task,
    doc_id: str,
    file_key: str,
    kb_id: str,
    stream_key: str
) -> dict:
    """异步解析文档"""
    
    # 1. 获取文件
    storage = get_storage()
    file_data = await storage.get(file_key)
    
    # 2. 解析文档
    dispatcher = DocumentDispatcher()
    parsed_doc = await dispatcher._dispatch_from_data(file_data, file_key, doc_id)
    
    # 3. 构建文档树
    tree_builder = TreeBuilder()
    tree = await tree_builder.build(parsed_doc.elements, doc_id)
    
    # 4. 保存树节点和元素
    await _save_tree_nodes_to_db(tree, doc_id)
    await _save_elements_to_db(parsed_doc.elements, doc_id, tree)
    
    # 5. 分块
    chunker = Chunker(chunk_size=512, chunk_overlap=50)
    chunks = await chunker.chunk(parsed_doc.elements, doc_id, kb_id)
    
    # 6. 保存 chunks
    await _save_chunks_to_db(chunks, doc_id, kb_id)
    
    # 7. 向量化
    embedder = Embedder()
    vector_count = await embedder.embed(chunks, kb_id)
    
    return {"status": "success", "chunks": len(chunks), "vectors": vector_count}
```

|------|------|------|
| `paragraph` | 普通段落 | 所有文档格式 |
| `heading` | 标题（含层级） | 所有文档格式 |

### DOCX 解析示例

```python
# backend/app/core/parser/docx_parser.py

class DOCXParser(BaseParser):
    async def parse(self, file_data: bytes, doc_id: str) -> ParsedDocument:
        """解析 DOCX 文档"""
        doc = Document(io.BytesIO(file_data))
        
        elements: List[DocumentElement] = []
        
        # 按顺序遍历段落和表格
        for child in doc.element.body:
            if child.tag.endswith('}p'):  # 段落
                para = Paragraph(child, doc)
                if not para.text.strip():
                    continue
                
                element = self._create_paragraph_element(para, elem_idx, doc_id)
                elements.append(element)
                
            elif child.tag.endswith('}tbl'):  # 表格
                table = Table(child, doc)
                element = self._create_table_element(table, elem_idx, doc_id)
                if element:
                    elements.append(element)
        
        return ParsedDocument(doc_id=doc_id, elements=elements, ...)
```

### 元素提取规则

#### 段落提取
- ✅ 提取所有非空段落
- ✅ 识别标题样式和编号标题
- ✅ 保留样式信息（用于判断标题层级）

#### 表格提取
- ✅ 提取所有表格
- ✅ 转换为 HTML 格式（用于展示）
- ✅ 同时保存纯文本格式（用于检索）

```python
def _extract_heading_level(self, para) -> int:
```

```python
    title: str                      # 节点标题（章节名）

```

### 树构建算法

```python
# backend/app/core/parser/tree_builder.py

async def build(self, elements: List[DocumentElement], doc_id: str) -> DocumentTree:
    """构建文档树"""
    
    # 1. 识别所有标题节点
    heading_nodes = []
    for elem in elements:
        if self._is_heading(elem):
            node = self._create_node(elem, doc_id)
            heading_nodes.append(node)
    
    # 2. 使用栈构建层级关系
    root = TreeNode(node_id='root', level=0, title='Root', ...)
    stack = [root]
    
    for node in heading_nodes:
        # 找到合适的父节点
        while len(stack) > 1 and stack[-1].level >= node.level:
            stack.pop()
        
        # 添加为子节点
        parent = stack[-1]
        parent.children.append(node.node_id)
        stack.append(node)
    
    # 3. 分配元素到节点
    self._assign_elements_to_nodes(elements, heading_nodes)
    
    return DocumentTree(root=root, nodes=heading_nodes)
```

### 元素分配规则

每个标题节点包含从它开始到下一个标题之间的所有元素：

```
元素列表:
[0] 第一章 招标公告 (heading, level=1)
[1] 段落文本...
[2] 表格数据...
[3] 1.1 项目概况 (heading, level=2)
[4] 段落文本...
[5] 第二章 投标人须知 (heading, level=1)
...

分配结果:
节点"第一章 招标公告" → 包含元素 [0, 1, 2, 3, 4]
节点"第二章 投标人须知" → 包含元素 [5, ...]
```

## 分块策略

### 当前策略：基于文本长度

```python
# backend/app/core/parser/chunker.py

class Chunker:
    def __init__(
        self,
        chunk_size: int = 512,      # 目标块大小（字符数）
        chunk_overlap: int = 50,    # 重叠字符数
        min_chunk_size: int = 100   # 最小块大小
    ):
        self.chunk_size = chunk_size
        self.chunk_overlap = chunk_overlap
        self.min_chunk_size = min_chunk_size
    
    async def chunk(
        self,
        elements: List[DocumentElement],
        doc_id: str,
        kb_id: str
    ) -> List[dict]:
        """分块处理"""
        
        chunks = []
        current_elements = []
        current_size = 0
        
        for elem in elements:
            # 只处理文本类型
            if elem.element_type not in ['paragraph', 'heading', 'list', 'table']:
                continue
            
            text_size = len(elem.content)
            
            # 检查是否需要新块
            if current_size + text_size > self.chunk_size and current_size >= self.min_chunk_size:
                # 保存当前块
                chunk = self._create_chunk_dict(current_elements, doc_id, kb_id)
                chunks.append(chunk)
                
                # 重叠处理
                overlap_elements = self._get_overlap(current_elements)
                current_elements = overlap_elements
                current_size = sum(len(e.content) for e in overlap_elements)
            
            current_elements.append(elem)
            current_size += text_size
        
        # 保存最后一块
        if current_elements and current_size >= self.min_chunk_size:
            chunk = self._create_chunk_dict(current_elements, doc_id, kb_id)
            chunks.append(chunk)
        
        return chunks
```

### 分块示例


## 向量化

### Embedding 流程

```python
# backend/app/core/parser/embedder.py

class Embedder:
    async def embed(self, chunks: List[dict], kb_id: str) -> int:
        """向量化 chunks"""
        
        # 1. 获取默认 embedding 模型
        model = await self._get_default_embedding_model(kb_id)
        
        # 2. 批量处理
        batch_size = 100
        vector_count = 0
        
        for i in range(0, len(chunks), batch_size):
            batch = chunks[i:i+batch_size]
            
            # 3. 调用 Embedding API
            texts = [chunk['content'] for chunk in batch]
            embeddings = await model.aembed_documents(texts)
            
            # 4. 更新数据库
            for chunk, emb in zip(batch, embeddings):
                await self._update_chunk_embedding(chunk['id'], emb, model.model_name)
                vector_count += 1
        
        return vector_count
```

## 检索流程

### 检索架构

EasyRAG 支持**混合检索**（Hybrid Search）：

```
用户查询
    ↓
    ├─→ 向量检索 (Vector Search)
    │    └─ 余弦相似度
    │
    ├─→ 关键词检索 (Keyword Search)
    │    └─ pg_trgm 三元组相似度
    │
    └─→ 元数据过滤 (Metadata Filter)
         └─ SQL WHERE 条件
```

### 向量检索

```python
# backend/app/core/retrieval/vector_search.py

async def search(
    q_emb: list[float],
    kb_ids: list[str],
    top_k: int,
    ...
) -> list[dict]:
    """向量检索"""
    
    sql = """
    SELECT 
        c.id, c.document_id, c.content,
        1 - (c.embedding <=> :emb) AS vector_score
    FROM chunks c
    JOIN documents d ON d.id = c.document_id
    WHERE d.kb_id = ANY(:kb_ids)
        AND d.enabled
        AND c.enabled
        AND c.embedding IS NOT NULL
    ORDER BY c.embedding <=> :emb
    LIMIT :top_k
    """
    
    rows = await session.execute(text(sql), {
        "emb": str(q_emb),
        "kb_ids": kb_ids,
        "top_k": top_k
    })
    
    return [_hit(row) for row in rows]
```

**关键点**：
- ✅ 使用 pgvector 的 `<=>` 算子计算余弦距离
- ✅ 返回向量相似度得分
- ✅ 支持元数据过滤（通过 CTE 优化）

### 关键词检索

```python
# backend/app/core/retrieval/hybrid_search.py

async def search(
    query: str,
    kb_id: str,
    top_k: int,
    ...
) -> list[dict]:
    """关键词检索"""
    
    # 降低相似度阈值以支持短查询
    await session.execute(text('SET pg_trgm.similarity_threshold = 0.01'))
    
    sql = """
    SELECT 
        c.id, c.document_id, c.content,
        similarity(c.content_search, :query) AS keyword_score
    FROM chunks c
    WHERE c.kb_id = :kb_id
        AND c.enabled
        AND c.content_search IS NOT NULL
    ORDER BY keyword_score DESC
    LIMIT :top_k
    """
    
    rows = await session.execute(text(sql), {
        "query": query,
        "kb_id": kb_id,
        "top_k": top_k
    })
    
    return [_hit(row) for row in rows]
```

**关键点**：
- ✅ 使用 pg_trgm 三元组相似度
- ✅ 支持模糊匹配（无需精确关键词）
- ✅ 降低阈值支持短查询

## 分块策略讨论

### 当前策略：基于文本长度

#### 优点
- ✅ 分块大小均匀（约 512 字符）
- ✅ 向量检索效果稳定
- ✅ 包含足够上下文
- ✅ 实现简单，性能可预测

#### 缺点
- ❌ 可能跨越章节边界（语义割裂）
- ❌ 短元素被合并，检索粒度粗
- ❌ 长元素可能被截断

### 替代方案：基于章节分块

#### 方案 A：一个章节一个 Chunk

```
第一章 招标公告 (5000字) → Chunk 1
第二章 投标人须知 (300字) → Chunk 2
第三章 评标办法 (2000字) → Chunk 3
```

**优点**：
- ✅ 保持语义完整性
- ✅ 符合用户直觉
- ✅ 检索结果更聚焦

**缺点**：
- ❌ Chunk 大小不均（300字 vs 5000字）
- ❌ 长章节检索粒度太粗
- ❌ 向量检索效果不稳定

#### 方案 B：章节 + 长度混合

```python
for node in tree_nodes:
    elements = get_elements_by_node(node)
    content = '\n\n'.join([e.content for e in elements])
    
    if len(content) <= 512:
        # 短章节：一个 Chunk
        chunks.append(create_chunk(content, node.title))
    else:
        # 长章节：按长度再分块
        sub_chunks = split_by_length(content, 512)
        chunks.extend(sub_chunks)
```

**优点**：
- ✅ 短章节保持完整性
- ✅ 长章节分块处理
- ✅ 平衡语义和检索效果

**缺点**：
- ❌ 实现复杂
- ❌ 需要处理跨子章节分块

### 建议方案

#### 当前场景（推荐）

**保持当前策略**，理由：
1. ✅ 检索效果稳定（实验验证）
2. ✅ 实现简单，性能可预测
3. ✅ 已有 `chunk_overlap` 缓解语义割裂
4. ✅ 元数据记录元素 ID，可追溯

#### 如果需要优化

**调整参数**：
```python
# 增大 chunk_size，包含更多上下文
chunker = Chunker(chunk_size=1024, chunk_overlap=100)

# 增大 overlap，减少语义割裂
chunker = Chunker(chunk_size=512, chunk_overlap=100)
```

**添加章节信息**：
```python
# 在 Chunk 元数据中添加章节信息
metadata = {
    'element_ids': [...],
    'element_types': [...],
    'section_path': '第一章 招标公告',  # 已有
    'section_level': 1,                  # 新增：章节层级
    'parent_sections': ['Root', '第一章'],  # 新增：父章节路径
}
```

这样在检索时可以：
- ✅ 按章节过滤
- ✅ 显示章节上下文
- ✅ 提高检索精度
