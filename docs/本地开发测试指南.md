# 本地开发测试指南

本文档说明如何在本地运行前后端测试，包括需要启动的服务和配置。

---

## 一、基础设施服务

本地开发需要连接虚拟机（192.168.137.13）上的基础设施服务：

| 服务 | 地址 | 用途 |
|------|------|------|
| PostgreSQL | 192.168.137.13:5432 | 数据库 |
| Redis | 192.168.137.13:6379 | **Celery Broker + 结果存储** |
| MinIO | 192.168.137.13:9000 | 对象存储 |
| Langfuse | 192.168.137.13:3030 | LLM 追踪（可选） |
| OpenSandbox | 192.168.137.13:8090 | 代码沙箱 |

**确认服务状态**：
```bash
# 检查 PostgreSQL
psql -h 192.168.137.13 -U easyrag -d easyrag_v2 -c "SELECT 1"

# 检查 Redis
redis-cli -h 192.168.137.13 -a easyrag2026 ping

# 检查 MinIO
curl http://192.168.137.13:9000/minio/health/live

# 检查 OpenSandbox
curl http://192.168.137.13:8090/health
```

## 二、后端测试

### 2.1 测试分类

根据测试类型，需要不同级别的服务：

| 测试类型 | 需要的服务 | 示例测试文件 |
|---------|-----------|-------------|
| 纯单元测试 | 无 | `test_sandbox.py` (Mock) |
| 模型测试 | 无 | `test_embedder.py`, `test_reranker.py` |
| API 测试 | PostgreSQL | `test_scenes_api.py` |
| 集成测试 | PostgreSQL + OpenSandbox | `test_sandbox.py` (Integration) |
| 工作流测试 | PostgreSQL + Redis + Celery Worker | `test_workflows_pg.py` |

### 2.2 运行测试

#### 快速测试（纯单元测试 + Mock）

**不需要任何服务**，适合快速验证：

```bash
cd D:/4-MyProject/EasyRag/backend

# 运行独立的单元测试
uv run pytest tests/test_sandbox.py tests/test_embedder.py tests/test_reranker.py tests/test_scenes_api.py -v

# 预期结果：25+ passed
```

#### 完整测试（需要数据库）

**需要 PostgreSQL 运行**：

```bash
cd D:/4-MyProject/EasyRag/backend

# 运行所有测试（跳过压力测试）
uv run pytest tests/ --ignore=tests/stress -v

# 运行特定模块
uv run pytest tests/test_sandbox.py -v
```

## 三、前端测试

### 3.1 Mock 模式

前端使用 Mock 模式，**不需要后端服务**：

```bash
cd D:/4-MyProject/EasyRag/frontend

# 安装依赖
pnpm install

# 启动开发服务器（Mock 模式）
pnpm dev
```

### 3.2 Mock 配置

**配置文件**：`frontend/.env.development`

```env
VITE_API_BASE=/api/v2
VITE_USE_MOCK=true  # 启用 Mock
```

**切换到真实后端**：

修改 `.env.development`：
```env
VITE_API_BASE=http://localhost:8000/api/v2
VITE_USE_MOCK=false
```

同时修改 `vite.config.ts` 启用代理：
```typescript
server: {
  port: 3000,
  proxy: {
    '/api': {
      target: 'http://localhost:8000',
      changeOrigin: true
    }
  }
}
```

## 四、后端服务启动

后端有**两个独立进程**：
1. **API 服务**：处理 HTTP 请求
2. **Celery Worker**：处理后台任务（工作流、解析等）

### 4.1 启动 API 服务

```bash
cd D:/4-MyProject/EasyRag/backend

# 启动开发服务器
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

# 访问 API 文档
# http://localhost:8000/docs
```

### 4.2 启动 Celery Worker

**Celery Worker 是独立进程**，负责从 Redis 队列获取任务并执行：

```bash
cd D:/4-MyProject/EasyRag/backend

# 启动 Celery Worker（所有队列）
uv run python celery_worker_main.py

# 启动指定队列
uv run python celery_worker_main.py -Q parse -c 4
uv run python celery_worker_main.py -Q workflow,agent -c 8

# 调试模式
uv run python celery_worker_main.py -l debug
```

**Celery 队列说明**：

| 队列 | 用途 | 并发建议 |
|------|------|---------|
| `default` | 默认任务 | 4 |
| `parse` | 文档解析 | 根据存储 I/O 调整 |
| `workflow` | 工作流执行 | 8-16 |
| `agent` | Agent 对话 | 4-8 |

### 4.3 启动 Celery Beat（定时任务，可选）

```bash
# 启动 Celery Beat 调度器
uv run python celery_beat.py
```

### 4.4 同时启动 API + Worker

**推荐方式**：使用两个终端窗口

```bash
# 终端 1: API 服务
cd D:/4-MyProject/EasyRag/backend
uv run uvicorn app.main:app --reload

# 终端 2: Celery Worker
cd D:/4-MyProject/EasyRag/backend
uv run python celery_worker_main.py
```

**或使用 Procfile**（可选）：
```bash
# 安装 honcho
uv pip install honcho

# 创建 Procfile
cat > Procfile << 'EOF'
web: uvicorn app.main:app --reload
worker: python celery_worker_main.py
EOF

# 同时启动
uv run honcho start
```

### 4.5 数据库迁移

```bash
cd D:/4-MyProject/EasyRag/backend

# 查看当前迁移状态
uv run alembic current

# 应用迁移
uv run alembic upgrade head

# 创建新迁移
uv run alembic revision --autogenerate -m "描述"
```

## 六、常见问题

### Q1: 测试失败提示 "relation does not exist"

**原因**：数据库表未创建

**解决**：
```bash
cd D:/4-MyProject/EasyRag/backend
uv run alembic upgrade head
```

### Q2: 测试失败提示 "connection refused"

**原因**：虚拟机服务未启动或网络不通

**解决**：
1. 确认虚拟机运行
2. 检查网络连接：`ping 192.168.137.13`
3. 检查服务状态（见第一节）

### Q3: 前端 Mock 不生效

**原因**：`.env.development` 配置错误

**解决**：
1. 确认 `VITE_USE_MOCK=true`
2. 重启前端开发服务器
3. 清除浏览器缓存

### Q4: OpenSandbox 测试失败

**原因**：OpenSandbox 服务未运行或配置错误

**解决**：
1. 检查服务：`curl http://192.168.137.13:8090/health`
2. 确认 `.env` 中有 OpenSandbox 配置（使用默认值即可）
3. 如需 API Key，添加：`OPENSANDBOX_API_KEY=easyrag2026`

### Q5: Celery Worker 无法连接 Redis

**原因**：Redis 服务未启动或配置错误

**解决**：
```bash
# 检查 Redis
redis-cli -h 192.168.137.13 -a easyrag2026 ping

# 确认 .env 配置
REDIS_URL=redis://:easyrag2026@192.168.137.13:6379
CELERY_BROKER_URL=redis://:easyrag2026@192.168.137.13:6379/0
```

### Q6: 工作流执行无响应

**原因**：Celery Worker 未启动

**解决**：
```bash
# 确认 Worker 运行
ps aux | grep celery

# 启动 Worker
uv run python celery_worker_main.py
```

### Q7: Celery 任务不执行

**原因**：队列名称不匹配

**解决**：
```bash
# 检查 Worker 监听的队列
uv run python celery_worker_main.py -Q parse,workflow,agent

# 检查任务提交的队列
# 确保任务提交到 Worker 监听的队列
```

## 七、推荐测试流程

### 完整开发环境

```bash
# 终端 1: API 服务
cd backend
uv run uvicorn app.main:app --reload

# 终端 2: Celery Worker
cd backend
uv run python celery_worker_main.py

# 终端 3: 前端（Mock 或连接后端）
cd frontend
pnpm dev
```

### 开发阶段（快速反馈）

```bash
# 1. 运行单元测试（快速）
uv run pytest tests/test_sandbox.py -v

# 2. 启动前端（Mock 模式）
cd ../frontend && pnpm dev
```

### 提交前验证

```bash
# 1. 运行所有非压力测试
cd backend
uv run pytest tests/ --ignore=tests/stress -v

# 2. 检查代码格式
uv run ruff check app/

# 3. 启动后端验证
uv run uvicorn app.main:app --reload
uv run python celery_worker_main.py
```

## 九、架构概览

```
┌─────────────────┐      ┌─────────────────┐      ┌─────────────────┐
│   前端 (Vue)    │─────▶│  API 服务       │─────▶│  PostgreSQL     │
│  localhost:3000 │      │  localhost:8000 │      │  192.168.137.13 │
└─────────────────┘      └─────────────────┘      └─────────────────┘
                                   │                        │
                                   │         ┌──────────────┘
                                   │         │ 数据
                                   ▼         ▼
                         ┌─────────────────────┐
                         │  Celery Worker      │◀────┐
                         │  (独立进程)          │     │
                         │  处理后台任务：      │     │
                         │  - 工作流执行        │     │
                         │  - 文档解析          │     │
                         │  - Agent 对话        │     │
                         └─────────────────────┘     │
                                   ▲                 │
                                   │ 任务队列        │
                         ┌─────────────────────┐     │
                         │   Redis             │─────┘
                         │   (Broker + Backend)│
                         │   192.168.137.13    │
                         └─────────────────────┘
```

**关键点**：
- ✅ Celery Worker 是**独立进程**
- ✅ 使用 **Redis** 作为 Broker 和结果存储
- ✅ 与 API 服务通过 Redis 队列通信
- ✅ 支持 4 个队列：default, parse, workflow, agent
