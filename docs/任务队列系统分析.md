# 任务队列系统分析报告

## 当前状态

项目**混合使用**两种任务队列系统：

| 功能 | 队列系统 | Broker | Worker |
|------|---------|--------|--------|
| **工作流执行** | PGJobQueue (PostgreSQL) | PostgreSQL | `pg_worker.py` |
| **文档解析** | Celery | Redis | `celery_worker_main.py` |
| **执行控制** | PGJobQueue | PostgreSQL | - |

---

## 详细分析

### 1. 工作流执行路径

**API 调用链**：
```
POST /workflows/{id}/execute
  ↓
enqueue_workflow_task()  # app/core/engine/arq_client.py
  ↓
PGJobQueue.enqueue()     # PostgreSQL 队列
  ↓
pg_worker.py             # 轮询 PostgreSQL 队列
```

**关键代码**：

`app/api/v2/workflows.py:166-184`:
```python
@router.post("/{wid}/execute")
async def execute(wid: str, body: ExecuteRequest, me=Depends(get_current_user)):
    """触发工作流执行：创建 execution + 入队 PG 任务，立即返回 executionId。"""
    exec_id = await enqueue_workflow_task(wid, body.inputs or {}, "manual", str(me.id))
    return ok({"executionId": exec_id, "status": "running"})
```

`app/core/engine/arq_client.py:56-65`:
```python
# 使用 PGJobQueue 入队任务
exec_id = await PGJobQueue.enqueue(
    session=s,
    workflow_id=wf.id,
    inputs=inputs or {},
    trigger=trigger,
    user_id=user_id,
    priority=0
)
```

**执行控制** (`app/api/v2/executions.py:58-97`):
```python
# 取消执行
await PGJobQueue.cancel(s, eid)

# 恢复执行
await PGJobQueue._requeue_paused(s, eid)
```

## 问题与建议

### 问题 1: Worker 进程需要启动两个

```bash
# 终端 1: PG Worker (工作流)
uv run python -m app.worker.pg_worker_main

# 终端 2: Celery Worker (文档解析)
uv run python celery_worker_main.py
```

### 问题 2: 依赖了两种 Broker

- **PostgreSQL**: 工作流队列 + 执行历史
- **Redis**: Celery broker + 结果存储

### 问题 3: 测试覆盖不一致

- `test_pg_worker.py` - 测试 PG Worker
- `test_workflows_pg.py` - 测试 PG 队列
- 文档解析测试：未使用 Celery

---

## 建议：统一到 Celery

### 方案 1: 完全迁移到 Celery（推荐）

**优势**：
- ✅ 统一的队列系统
- ✅ 成熟的监控工具（Flower）
- ✅ 更好的任务重试机制
- ✅ 分布式友好

**迁移步骤**：

1. **创建 Celery 任务**替代 `pg_worker.py`:

```python
# app/worker/tasks/workflow_tasks.py
@celery_app.task(bind=True, max_retries=3)
def execute_workflow(self, execution_id: str, definition: dict, inputs: dict):
    """工作流执行任务"""
    # 从 PGJobQueue 逻辑迁移过来
    ...
```

2. **修改 `enqueue_workflow_task()`**:

```python
# app/core/engine/arq_client.py
async def enqueue_workflow_task(...) -> str:
    # 创建执行记录
    ...
    exec_id = str(execution.id)

    # 提交 Celery 任务
    task = celery_app.send_task(
        "execute_workflow",
        args=[exec_id, definition, inputs],
        queue="workflow"
    )

    return exec_id
```

3. **迁移执行控制**:

```python
# 取消：Celery 支持任务撤销
celery_app.control.revoke(task_id, terminate=True)

# 暂停/恢复：需要配合检查点机制
```

4. **更新 API 路由**:

```python
# app/api/v2/executions.py
# 不再使用 PGJobQueue，改用 Celery API
```

---

### 方案 2: 完全迁移到 PGJobQueue

**优势**：
- ✅ 只依赖 PostgreSQL
- ✅ 简化架构
- ✅ 与现有工作流执行一致

**迁移步骤**：

1. **创建 PG 任务**替代 Celery:

```python
# app/worker/tasks/parse_tasks.py
# 从 @celery_app.task 改为 PG Worker 处理
async def parse_document(doc_id: int, file_key: str, kb_id: int):
    ...
```

2. **修改 `DocumentServiceV2`**:

```python
# 使用 PGJobQueue.enqueue
await PGJobQueue.enqueue_task("parse_document", {...})
```

---

## 推荐方案

**推荐：方案 1（统一到 Celery）**

理由：
1. Celery 是成熟的任务队列系统，功能完善
2. 已有 `CELERY_SETUP.md` 文档
3. `document_service_v2.py` 已经使用 Celery
4. 可使用 Flower 监控
5. 支持任务重试、优先级、路由等高级特性

## 当前启动方式

由于混合使用，完整环境需要：

```bash
# 终端 1: API 服务
uv run uvicorn app.main:app --reload

# 终端 2: PG Worker (工作流)
uv run python -m app.worker.pg_worker_main

# 终端 3: Celery Worker (文档解析)
uv run python celery_worker_main.py

# 终端 4: 前端
cd ../frontend && pnpm dev
```
