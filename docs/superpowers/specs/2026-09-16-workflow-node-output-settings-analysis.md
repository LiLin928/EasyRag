# 工作流节点输出设置分析报告

**日期：** 2026-09-16
**分析范围：** 所有工作流节点类型的输出设置和配置
**目标：** 识别需要改进的配置项，提升用户体验

---

## 执行摘要

本次分析覆盖了 EasyRAG 工作流编辑器中的 **13 种节点类型**，发现以下主要问题：

1. **硬编码配置问题**：LLM 模型选择、知识库选择等配置项使用硬编码，未与系统设置集成
2. **输出变量定义不友好**：用户需要手动输入提取路径，容易出错
3. **配置项缺失**：部分节点缺少重要配置项（如 RAG 的 embedding 模型选择）
4. **系统数据源未集成**：知识库、模型、工具等应从系统设置获取，而非硬编码

### 2. RAG 检索节点 ⚠️ 需要改进

**当前配置项：**
- 知识库选择（硬编码选项：`kb-1`, `kb-2`）
- Top K 参数
- 相似度阈值

**默认输出参数：**
- `result` - 检索结果
- `documents` - 文档列表
- `context` - 上下文

**问题识别：**

#### 问题 2.1：知识库选择硬编码
**位置：** `NodeConfigModal.vue:313-320`

**当前实现：**
```vue
<el-select v-model="form.config.kbIds" multiple placeholder="选择知识库">
  <el-option label="知识库 A" value="kb-1" />
  <el-option label="知识库 B" value="kb-2" />
</el-select>
```

**问题：** 知识库选项硬编码，未从系统获取真实知识库列表

**改进建议：**
- 从 `useKnowledgeStore()` 获取知识库列表
- 显示知识库状态（文档数量、向量模型等）
- 支持筛选和搜索

#### 问题 2.2：缺少 Embedding 模型选择
**问题：** RAG 检索依赖 Embedding 模型，但配置界面未提供选择

**改进建议：**
- 从系统设置获取 Embedding 模型列表
- 显示默认模型
- 允许用户选择不同的 Embedding 模型

#### 问题 2.3：输出变量定义不友好
**问题：** 用户需要手动输入 `documents`, `context` 等提取路径

**改进建议：**
- 提供输出变量预设选项：
  - `documents` - 检索到的文档列表
  - `context` - 拼接后的上下文
  - `scores` - 相似度分数
  - `query` - 查询文本

## 改进方案

### 方案 A：渐进式改进（推荐）

**策略：** 按优先级逐步改进，先解决高优先级问题

**优点：**
- 风险小，每步可验证
- 用户可快速看到改进
- 便于收集反馈

**缺点：**
- 总体时间较长
- 可能需要多次重构

**步骤：**
1. 立即改进 RAG 检索节点
2. 后续改进模板渲染节点
3. 根据反馈改进其他节点

---

### 方案 B：一次性全面改进

**策略：** 一次性改进所有中高优先级节点

**优点：**
- 一次性解决所有问题
- 统一改进体验

**缺点：**
- 风险大，难以验证
- 工作量大
- 可能引入新问题

---

### 方案 C：用户驱动改进

**策略：** 根据用户反馈决定改进优先级

**优点：**
- 改进更有针对性
- 用户参与决策

**缺点：**
- 可能错过关键问题
- 时间不可控

---

## 推荐方案

**推荐：方案 A - 渐进式改进**

**理由：**
1. RAG 检索节点是核心功能，知识库选择硬编码严重影响使用
2. 渐进式改进风险可控，便于验证

4. 便于根据反馈调整后续改进
