## 🚀 实施建议

### 执行顺序

1. **Phase 1** → **立即开始**（补完现有功能，消除技术债）
2. **Phase 2** → **Phase 1 完成后**（核心功能，工作流引擎）
3. **Phase 2.5** → **Phase 2 并行或随后**（检索增强）
4. **Phase 3** → **Phase 2 完成后**（工具链，依赖工作流）
5. **Phase 5** → **Phase 2 完成后**（待办，依赖工作流）
6. **Phase 4** → **Phase 3 完成后**（智能体，依赖工具链）

### 开发原则

1. **TDD 驱动**: 先写测试，再写实现
2. **渐进式交付**: 每个阶段独立可用，可测试
3. **持续集成**: 每个 Task 完成后提交，确保主分支稳定
4. **API 契约优先**: 严格遵循前端 mock 定义
5. **文档同步更新**: 代码和文档同步维护

### 技术栈确认

| 组件 | 当前版本 | 是否需要升级 |

## ⚠️ 风险和缓解措施

### 技术风险
1. **LangGraph 学习曲线**
   - 缓解: 先实现简单流程，逐步增加复杂度
   - 预留: 2天调试时间

2. **SSE 连接稳定性**
   - 缓解: 实现重连机制，心跳检测
   - 测试: 压力测试长连接

3. **工作流状态持久化**
   - 缓解: PostgresSaver 配置验证
   - 备选: Redis 持久化方案

### 进度风险
1. **估算偏差**
   - 缓解: 每日站会跟踪进度
   - 应对: 调整优先级，砍掉非核心功能

2. **依赖阻塞**
   - 缓解: 提前识别依赖，并行准备
   - 应对: Mock 实现，先跑通流程
